# MCT 밀링 G/M 코드 조사 노트

## 결론: 제어기 프로파일이 먼저다

G코드는 모달 상태를 바꾸며, 한 NC 블록에는 여러 명령과 주소값이 함께 들어갈 수 있습니다. RS274/NGC 문서도 한 줄을 블록으로 설명하고, motion mode가 다음 블록에 이어질 수 있다고 정의합니다. 따라서 코드는 줄마다 독립적으로 숫자만 읽는 방식이 아니라 단위·평면·좌표 모드·이송 모드·주축 상태를 유지하는 인터프리터로 해석해야 합니다. [LinuxCNC G-code 개요](https://linuxcnc.org/docs/html/gcode/overview.html), [LinuxCNC 코드 빠른 참조](https://www.linuxcnc.org/docs/html/gcode.html)

G/M 코드 의미는 제어기별로 다릅니다. 예를 들어 Haas 밀링 문서는 M07을 샤워 냉각수로 설명하고, M10/M11은 4축 브레이크, M70/M71은 워크홀딩, M97/M98은 서브프로그램과 연결합니다. LinuxCNC의 같은 코드 목록과 기능은 완전히 같지 않습니다. 그래서 특정 MCT/제어기·옵션이 정해지지 않은 현재는 ISO/RS274 공통 기능만 처리하고, 미지원·옵션 코드는 보수적으로 정지해야 합니다. [Haas Mill M-code 목록](https://haascnc.com/service/service-content/guide-procedures/mill---m-codes.html), [LinuxCNC M/G 코드 참조](https://www.linuxcnc.org/docs/html/gcode.html)

## 시뮬레이터의 모달 상태

| 영역 | 공통 코드 | 상태/기능 |
|---|---|---|
| 보간 | G0, G1, G2, G3 | 급속·직선 이송·시계/반시계 방향 원호 |
| 평면/단위 | G17, G20, G21 | XY 원호 평면 및 inch/mm 단위 |
| 좌표 | G90, G91, G54 | 절대·증분 위치, 현재 설정한 작업 원점 |
| 드릴 사이클 | G73, G80, G81, G82, G83, G98, G99 | 칩 브레이크/기본 드릴/정지/펙 드릴, 사이클 취소, 복귀 평면 |
| 공구 길이 | G43 Hnn, G49 | 단일 설정 H 길이 보정 적용/취소 |
| 이송 | F, G94 | 분당 이송량 |
| 주축 | S, M3, M4, M5 | 속도 지령·정회전·역회전·정지 |
| 공구 | T, M6 | 공구 선택·교환 상태 |
| 부가 장치 | M7, M8, M9 | 냉각수 상태 |
| 프로그램 | M0, M1, M2, M30 | 정지·선택 정지·종료/리셋 |

이 표는 현재 프로토타입이 해석하는 제한된 코드 묶음입니다. 모든 CNC 제어기나 ISO 6983 기능을 지원한다는 의미는 아닙니다. 원호는 XY 평면에서 I/J 또는 R을 다루며, 기본 0.5 mm XY 소재 셀로 이산화합니다. G43은 화면에서 설정한 단일 H 번호/길이만 사용합니다. G18/G19 원호, I/J 절대 중심 모드, 나사 가공·프로브·스플라인·매크로 및 서브프로그램은 실제 이동을 결정하므로 현재 블록 검증을 중단합니다.

## M코드의 검증 의미

M코드는 보통 형상보다 기계 상태에 영향을 줍니다. M3/M4/M5를 주축 상태로 유지하고, M6는 활성 공구를 바꾸며, M7/M8/M9는 냉각수 상태를 기록합니다. M0/M1은 실행을 멈추고, M2/M30은 이후 블록 실행을 종료합니다. 옵션 M코드(팔레트, 브레이크, 클램프, 도어, 사용자 릴레이 등)는 기계별 설정과 인터록을 알기 전에는 안전 동작을 추정할 수 없으므로 미지원 처리해야 합니다.

Haas 2023 밀링 매뉴얼은 프로그램을 준비, 절삭, 종료 구간으로 설명하며 공구/워크 오프셋, 주축, 냉각수, 위치 모드가 준비 단계에 포함된 예제를 보여줍니다. 또한 같은 블록에 여러 G코드를 둘 때는 서로 다른 그룹이어야 하고, 해당 매뉴얼은 블록당 M코드 하나를 요구합니다. 구현에서는 서로 충돌하는 모달 그룹을 막고, 복수 M코드는 제어기 프로파일이 확정될 때까지 실행을 멈춥니다. [Haas Mill 기본 프로그래밍](https://www.haascnc.com/service/online-operator-s-manuals/mill-operator-s-manual/mill---basic-programming.html)

## 이 프로토타입이 형상을 계산하는 방법

소재는 XY 0.5 mm 셀마다 남은 표면 높이를 저장하는 높이맵입니다. 평엔드밀의 원형 단면을 공구 경로를 따라 쓸어 셀의 높이를 낮춥니다. 이 방식은 3축 수직 밀링의 위에서 열린 포켓·면삭 형상과 제거 체적을 빠르게 그리는 **2.5D 근사**입니다. 완전한 3D voxel/solid Boolean 커널처럼 임의의 언더컷, 기울어진 공구축, 다축 형상을 표현하지 않습니다.

충돌 검사는 설정한 G54 기계 원점/축 범위, 이산화된 급속 이동과 남은 소재, 단순 전면·후면 바이스 죠, 설정한 공구 날장·돌출 길이·홀더 외경을 대상으로 합니다. 확인된 교차는 잠재 간섭 경고입니다. 정확한 검증은 기계 CAD/키네마틱스, 포스트프로세서와 제어기 사양, 실제 공구·홀더·치구 모델 및 측정된 오프셋을 함께 써야 합니다. VERICUT의 설명도 포스트된 NC 프로그램을 검증하고 기계·공구·홀더·치구·소재 구성요소의 이동을 검사하는 전체 기계 시뮬레이션을 구분해 설명합니다. [VERICUT 공식 제품 설명](https://vericut.com/hubfs/PDF/24_P1045_Vericut_Corporate%20Brochure_DIGITAL_RGB_AW.pdf)

## 실제 검증 수준으로 올리기 위한 다음 데이터

1. 장비 제조사/모델, 제어기 모델·세대·버전, 활성 옵션과 파라미터
2. 기계 축 구성/이동 범위, 회전축 중심, 공구교환 위치를 포함한 기계 모델
3. 사용할 포스트프로세서가 출력하는 코드와 안전 시작/종료 형식
4. 공구 테이블의 공구번호별 직경·날장·홀더·게이지 길이, 실제 보정값
5. G54-G59 및 공작물 원점, 실제 소재/치구/바이스 형상
6. 대표 NC 파일과 기계에서 검증된 결과/충돌 사례

첫 적용 대상을 특정한 뒤에는 해당 제어기 문서로 명령 해석을 맞추고, 알려진 기준 NC 프로그램과 결과를 대조하는 회귀 검증을 추가해야 합니다. 장비별 데이터가 없는 공통 프로파일은 실제 가공 승인 도구가 될 수 없습니다.
